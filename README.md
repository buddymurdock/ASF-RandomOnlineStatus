# ASF-RandomOnlineStatus

Плагин для **[ArchiSteamFarm](https://github.com/JustArchiNET/ArchiSteamFarm)**, который для каждого залогиненного бота имитирует день живого человека: длинные блоки "оффлайн"/"онлайн" по несколько часов, а внутри "онлайн"-блока — более частая смена того, чем бот "занят" (игра/простой), вместо того чтобы неделями висеть в одном и том же виде, как это обычно бывает у ботов.

У каждого бота свой независимый цикл, устроенный в два уровня:

1. **Блок оффлайн/онлайн.** После логина (и после каждого предыдущего блока) бот ждёт случайное число минут в диапазоне `[MinDelayMinutes; MaxDelayMinutes]` — это и есть длительность нового блока — и один раз разыгрывает, будет ли этот блок оффлайн (70%) или онлайн (30%). Это верхнеуровневое решение держится на всю длительность блока: бот не мигает статусом каждые полчаса, а "спит" или "сидит в сети" часами, как реальный человек.
2. **Под-состояние внутри онлайн-блока.** Пока блок онлайн, каждые `[SubStateMinDelayMinutes; SubStateMaxDelayMinutes]` минут (более короткий диапазон) бот заново разыгрывает, чем занят прямо сейчас:

| Под-состояние | Вероятность (внутри онлайн-блока) | Что происходит |
| --- | --- | --- |
| Основная игра | 70% | Запускается одна игра из `MainGameAppIDs`, реально принадлежащая этому боту. |
| Без игры | 15% | Онлайн, никакая игра не запущена. |
| Случайная игра | 15% | Запускается случайная игра из всей библиотеки бота. |

В сумме по времени это даёт примерно 70% оффлайн / 21% основная игра / 4.5% без игры / 4.5% случайная игра — но длительность самих блоков (часы) не зависит от того, оффлайн он или онлайн, поэтому это разделение на два уровня не искажает пропорцию 70/30, а только убирает "дёрганость" статуса.

> `GetOwnedGames` возвращает вообще всё, что есть в библиотеке бота, включая саундтреки, DLC и утилиты без геймплея — для состояния "случайная игра" плагин не фильтрует их отдельно (в API нет надёжного способа отличить играбельный тайтл от остального). На практике это может изредка привести к тому, что бот "запустит" что-то не совсем похожее на игру — это известное ограничение, не баг.

**Важно про фарм карточек.** `Bot.Actions.Play()` (то, чем ASF реально переключает игру) внутри сам ставит `CardsFarmer` на паузу — это поведение самого ASF, не этого плагина. Поэтому:

- Если бот **в момент розыгрыша уже реально фармит карточки** — плагин ничего не трогает в плане игры (только статус Online/Invisible). Настоящий фарм и так выглядит как "человек играет в игру", подделывать нечего, а прерывать его ради симуляции — вредно.
- Игра запускается только когда фармить нечего (бот простаивает).
- При переходе в "оффлайн" или "онлайн без игры" плагин сам вызывает `Bot.Actions.Resume()`, если это именно он запускал игру — иначе бот рисковал бы навсегда остаться на паузе фарма после первой же симуляции.
- Если вы вручную поставите бота на паузу командой ASF в момент, когда у плагина была активна симулированная игра, следующий тик плагина может её снять своим `Resume()` — ASF не различает, кто и почему поставил бота на паузу.

При дисконнекте бота его цикл останавливается, и на всякий случай сразу вызывается `Bot.Actions.Resume()` (это безопасный no-op, если фарм и не был на паузе) — так бот не может застрять в постоянной паузе фарма, если дисконнект произошёл прямо посреди симулированной игры. Цикл запускается заново при следующем логине.

## Установка

1. Скачайте архив плагина из [Releases](../../releases) и распакуйте в папку `plugins` рядом с ASF (создайте подпапку с именем плагина).
2. Перезапустите ASF.

## Конфигурация

Настройки задаются **глобально**, в `ASF.json`, как дополнительные (нераспознанные ASF) свойства верхнего уровня:

```json
{
	"RandomOnlineStatusEnabled": true,
	"RandomOnlineStatusMinDelayMinutes": 120,
	"RandomOnlineStatusMaxDelayMinutes": 480,
	"RandomOnlineStatusSubStateMinDelayMinutes": 15,
	"RandomOnlineStatusSubStateMaxDelayMinutes": 90,
	"RandomOnlineStatusMainGameAppIDs": [730, 570],
	"RandomOnlineStatusOwnedGamesCacheHours": 24
}
```

| Свойство | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `RandomOnlineStatusEnabled` | `bool` | `false` | Включает/выключает плагин. |
| `RandomOnlineStatusMinDelayMinutes` | `ushort`, минуты | `120` | Нижняя граница длительности одного блока оффлайн/онлайн. |
| `RandomOnlineStatusMaxDelayMinutes` | `ushort`, минуты | `480` | Верхняя граница длительности одного блока оффлайн/онлайн. |
| `RandomOnlineStatusSubStateMinDelayMinutes` | `ushort`, минуты | `15` | Нижняя граница паузы между розыгрышами под-состояния (игра/простой) внутри онлайн-блока. |
| `RandomOnlineStatusSubStateMaxDelayMinutes` | `ushort`, минуты | `90` | Верхняя граница паузы между розыгрышами под-состояния внутри онлайн-блока. |
| `RandomOnlineStatusMainGameAppIDs` | `uint[]` | `[]` | Пул "основных" игр (Steam AppID). Для под-состояния "основная игра" бот берёт пересечение этого пула со своей реальной библиотекой; если пересечение пустое — один раз пишет предупреждение и остаётся без игры в этом розыгрыше. |
| `RandomOnlineStatusOwnedGamesCacheHours` | `ushort`, часы | `24` | Как долго кэшировать список игр, реально принадлежащих боту (`GetOwnedGames` — сетевой запрос), прежде чем запросить заново. |

Если в любой из пар `MinDelayMinutes` больше `MaxDelayMinutes`, значения меняются местами автоматически. Веса состояний (70% оффлайн, 70/15/15% под-состояний онлайн-блока) сейчас не конфигурируются — если понадобится гибче, дайте знать.

> Начиная с этой версии плагин работает по-другому: вместо плоской ротации по списку `RandomOnlineStatusStatuses` (версия 1.0.0.0) — состояние-машина с оффлайном/игрой, описанная выше. `RandomOnlineStatusStatuses` больше не используется, если он есть в вашем `ASF.json` — можно убрать.

## Сборка

Проект использует **[ASF-PluginTemplate](https://github.com/JustArchiNET/ASF-PluginTemplate)** и собирается вместе с исходниками ASF, подключёнными как git submodule:

```sh
git clone --recurse-submodules https://github.com/buddymurdock/ASF-RandomOnlineStatus.git
cd ASF-RandomOnlineStatus
dotnet build -c Release
```

Если репозиторий уже склонирован без `--recurse-submodules`, подтяните submodule отдельно:

```sh
git submodule update --init --recursive
```
